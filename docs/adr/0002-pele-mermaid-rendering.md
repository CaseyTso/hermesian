# Replace Obsidian's built-in Mermaid rendering with pele

Hermesian's sidebar conversation previously relied on Obsidian's built-in `MarkdownRenderer` to render Mermaid code blocks after each turn completed. This produced diagrams whose colors and fonts did not adapt to the active Obsidian theme, and whose sizing in the narrow sidebar was often poor. The user experience was further limited by the lack of interactive controls for inspecting, exporting, or copying diagrams.

Pele, a standalone Mermaid renderer developed by the Obsidian team, was adopted to replace the built-in rendering. Pele renders diagrams synchronously to SVG using CSS variables for colors and fonts, making it naturally theme-adaptive and fast. All diagram types in Mermaid 12.1.0 are registered upfront for maximum compatibility with unpredictable AI output.

The trade-off is increased bundle size and maintenance responsibility: pele is a new dependency (approximately 200-300KB minified) and hermesian now owns the Mermaid rendering behavior rather than delegating to Obsidian. Additionally, a custom Diagram Surface component was built to host the rendered SVG and provide three user-facing actions: full-size inspection in a Host-Native Modal, export as PNG (copy to clipboard or save to filesystem via system dialog), and copy the rendered Mermaid source text. Rendering failures degrade gracefully to an error notice with expandable source, preserving the original Mermaid text for debugging. In the narrow sidebar, simple diagram types (flowchart, pie, etc.) scale to fit the container width, while inherently wide types (sequence, er, etc.) keep their original size with horizontal scrolling.

The alternative of patching Obsidian's built-in Mermaid output with CSS overrides was rejected because it could not solve the layout and sizing problems, and would remain fragile across Obsidian updates. The alternative of waiting for Obsidian to adopt pele natively was rejected because the timeline was uncertain and the user pain was immediate.

This decision is hard to reverse because removing pele would require either reverting to the inferior built-in rendering or building a custom SVG pipeline from scratch. Future readers should know that pele's CSS variable approach is the core enabler of theme adaptivity, and that the Diagram Surface's export actions were deliberately designed to use Electron's system save dialog (allowing filesystem-wide saves) rather than restricting to vault-only paths.
