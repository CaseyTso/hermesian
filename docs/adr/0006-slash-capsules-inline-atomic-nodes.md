# Slash capsules are inline atomic nodes inside the composer draft

Skill and command capsules produced by the slash menu used to live as a sibling DOM node outside the contenteditable draft, which made them unreachable by text selection and left deletion paths (Backspace at an empty draft, delete-over-selection) silently skipping them — users could not remove a capsule at all. We decided capsules live inside the draft as inline atomic nodes, reusing the composer's existing inline-capsule machinery: caret movement and selection treat a capsule as one indivisible unit, deletion removes it whole, and it stays pinned at the start of the text because send-time serialization always emits it as a fixed `/skill <name>` / `/<command>` prefix.

Considered options: keeping the external node and patching keyboard semantics only (rejected: selection-based deletion stays impossible by construction, and the external node duplicates a second capsule representation); free placement anywhere in the text (rejected: placement freedom is illusory since serialization fixes the prefix, and it would invite misunderstanding). The trade-off accepted is real: inline nodes require reworking serialization, paste/cut, and IME interaction around atomic spans.
