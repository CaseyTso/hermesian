# Steer outcome is receipt-authoritative; silence means applied

Hermesian used to verify a Steer by watching the live session stream for one verbatim English confirmation sentence, and reported "Steer could not be verified. Draft kept." whenever that sentence never arrived (model rephrasing, other languages, or the 30s timeout). That turned successful steers into false failures and made users resend guidance. We decided the explicit receipts Hermes returns (applied / queued / failed) are the only authority for a Steer's outcome: explicit rejection or a dead session keeps the draft with a red error; a queued receipt clears the draft and records a queued Steer Record; a request that returns with no receipt at all counts as applied, clears the draft, and records a Steer Record. Verbatim stream matching is removed.

Considered options: keeping verbatim matching (rejected: the steer RPC resolves right after injection, so the request response is already strong delivery evidence, and the sentence match only adds false negatives); fuzzy keyword matching (rejected: still pattern-matching model prose, same failure class with softer edges).

Amendment (steer UX polish, same authority): the *presentation* of a failed outcome changed from a red error Notice to a silent draft restore plus a gentle inline hint (e.g. "Steer did not land — your text is back in the composer."). The receipt remains the only authority and the draft is still never lost; only the alarm styling was dropped, matching the Hermes desktop client's never-lose-words, no-error-dialog philosophy. An in-flight steer now clears the draft immediately and shows a "steering" chip above the composer; on failure the text returns to the composer and the chip is removed.

Amendment 2 (server-semantics alignment): the Hermes ACP adapter absorbs a busy-session `session/prompt` either by mid-turn redirect or by queueing it for a later server-initiated turn; both outcomes are announced as standalone receipt sentences on the session stream. Hermesian therefore keeps a receipt filter (exact receipt sentences are suppressed from the assistant stream) but drops the capture-and-replay buffer entirely: main-turn prose always streams live and is never re-emitted, and server-initiated turns are split on their `user_message_chunk` echo so each turn finalizes (Markdown-renders) on its own boundary.
